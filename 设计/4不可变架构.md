# 不可变架构

不可变架构最近几年随着Docker而广为人知的一个架构原则。

    传统Linux上很容易AB两个软件互相协作，缺彼此依赖各不相同的依赖库，他们的依赖库彼此干扰，很难正常运行的问题。 
    Docker的出现，解决了这个问题。每个Docker容器都是一个当前软件高度适配的Linux环境。 
    Docker管这种架构叫做不可变基础设施。

实际上，整个软件架构设计发展的历史就是不可变架构发展的历史。 无论是面向对象、模块化变成、面向接口开发、领域驱动……其核心思想都是不可变设计。

无非这个不可变的对象是细粒度的代码、粗粒度的模块、或彼此交互的契约。

因为软件发展的80年历史，就是对抗复杂性的历史，就是对抗变化的历史。

# 化变化为不变

变化是不可避免的。软件架构设计的核心就是如何将变化化为不变。

![不可变架构](../img/不可变架构.png)     

如果一个架构，由组件组成。

1，任意业务的变化都可以表达为组件的某些配置，通过DSL配进去。

2，所有组件对其他组件而言都是确定的，不变的。

那么，这个架构必然是可靠的，可扩展的。


# 不可变架构最佳实践

| 配置表   | 屏蔽业务参数变化  |                      | 
| 流程编排  | 屏蔽流程变化    | pipeline,pc,liteflow |
