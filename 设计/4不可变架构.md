# 不可变架构

Docker把这东西带火的。把软件对环境依赖的不确定性，锁死成一个镜像。下面稳了，上面才玩得出编排、弹性、调度。否则一切建在流沙上。

JS也是。模块化规范出来之前，搞了十多年，浏览器里跑跑小脚本。规范一落地，前端几年就炸开了，反过来抢后端的地盘，WASM都出来了。不可变契约，涌现。

但世界本身是变的。不可变架构的关键不是否认变化——是把每种变化关进一个盒子。盒子对外不可变。

一切的变化，原子层无非是流程、逻辑、数据、服务、基础设施、组合关系……现在针对这些变化都有办法。

| | 屏蔽什么 | 用什么 |
|---|---|---|
| Docker | 基础设施 | Docker |
| 脚手架 | 技术组件 | springcloud |
| 网关 | 服务协议 | apisix、业务网关 |
| ETL | 数据源 | spark |
| API | 实现 | — |
| EL | 数据格式 | mvel、ognl |
| 配置文件 | 环境 | — |
| 配置表 | 业务参数 | — |
| 流程编排 | 流程 | pipeline、pc、liteflow |
| PaaS | 某类通用技术能力 | redis、监控 |
| APaaS | 某类通用业务能力 | 渠道网关、费率平台 |
| 引擎 | 多种变化的组合 | 浏览器、风控引擎 |
