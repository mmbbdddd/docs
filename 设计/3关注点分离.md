# 关注点分离

MVC是最出名的例子。
V交给前端和产品，C交给后端和业务，中间用数据模型隔开。各干各的。

这个道理谁都懂。但做的时候，全反着来。

让技术学业务，让产品学技术，都想培养全才。没什么效果。
搞产品、架构、PM三驾马车并行，照样难产。

让人全知全能，不是出路。分离，单一职责，做精。然后定义一套规范，让他们能接起来。这才是出路。

阿里中台，技术上其实没什么问题。Halo、Cola做流程编排，ExpressQL做表达式引擎，该覆盖的都覆盖了。

但中台团队成了效率单点。不是按需求响应，是按利益响应。再加上没有增量市场，只能在存量系统里搞重构——下雨天修房子，拆一面墙塌一面。阿里、恒生、赢时胜，原地重构的，没一个跑出来。

不是缺技术。阿里不缺。不是缺业务。恒生不缺。很多人既懂业务，也懂技术。

问题是复杂度全压在一个角色上。没分开。

出路在哪，我也没完全想清楚。

每一种技术方案，都有。每一种人才，都有。想让他们融合的愿景，也有。

但怎么让他们各自单一、又能拼到一起——这个没找到。

TOGAF那套协作流程和提交物规范，也许是个方向。

路子不在某个人的主动推动，而必须高层清晰的知道愿景蓝图是什么，PUSH团队克服困难去实现它。
