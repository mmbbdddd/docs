# 如何快速掌握一个业务领域

基本思想方法来自DDD

DDD的思想是系统的核心复杂度在业务，业务的核心复杂度在领域，领域的核心复杂度在聚合根

聚合根就比如一颗大树的根、大树无论如何枝叶繁茂，每个枝叶都必然和根中的某个毛细血管相连。

同理，DDD设计中认为，无论软件多么复杂，每个逻辑片段必然和聚合根中的某个数据项、或者值相关。

掌握了这一个点，就掌握了整个系统。

比如，经验丰富的支付系统专家，对着支付订单的订单对象，就大致能猜测出系统有那些模块，功能，什么流程。

# 事件风暴
 
    1，聚合根为起点
    2，以流程为依据
    3，梳理、头脑风暴流程中每个点可能的业务变化

经过事件风暴过的设计，大概率在流程上是完整的、在功能上能覆盖未来短期一段事件内的变化。

# ERP
交易角色：客户，供应商

交易结构：

        1. 订单=>库存=>销售回款=>账户
        2. 订单=>BOM=>采购单=>库存=>应付
        3. 订单=>生产单=>物料单=>库存单=>产品单=>库存
分析价值流

        最短链路意味着最快周转率、最大利润。尽量最求1模式（有一定产品库存，大小接近销售头寸）
        模式3 周期产出 = 模式1。确保生产、销售效率最高。
        应付周期略大于应收、可以实现0成本扩张。

# 清算

    交易角色：业务系统、内部账户、清算、外部账户
    交易结构：
        1，用户支付
            用户银行账户--
            平台银行账户++
            平台账户--
            平台商户账户++（冻结状态）
        2，清算
            平台商户账户--（冻结状态）
            平台商户待结算账户++   T0
            平台渠道待结算账户++   M0 （渠道费，笔数）
            ......
        3，TO结算
            平台商户待结算账户--    
            平台账户++     
            商户银行账户++
            平台银行账户--
        价值链分析：
            同一账户轧差可以极大减少渠道费用。
            清算是个资金池。截留了一部分商户、渠道资金的时间。    
            如果结算采用手工体现，会进一步加大这个资金量。
            交易量稳定的情况下，自然流入足以覆盖流出，并且有剩余。
