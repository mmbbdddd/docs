# AI的思考

去年10月份，参加大连项目。这个项目因为风险性过高，公司调来了CTO和7倍的人力资源投入（20人增长到150人）加班。

当然，根本的原因还是客户，普通客户类似项目大概只有600个需求。这个客户直接怼出了5000个需求，并且不接受砍需求
不接受分期。

公司只能向下转移压力，猛猛投入资源，猛猛加班。

最初我想引入AI，对开发进行提效。可面临几个困难

- 行业术语大模型不理解
- 公司用的技术框架是自研的。大模型写不出符合我们公司规范的代码。（我们的代码一半都是json）

开发很难简单的直接用提示词，让大模型写出符合我们要求的代码。



# Spec驱动

于是我花费了5天，指挥AI整理了公司的技术框架规范、行业属于规范……等。

在每个开发任务之前，让AI先读一遍规范，然后再输入提示词，就基本上能写出符合我们要求的代码了。
 

# 上下文工程：空间索引

不过，使用过程中发现长任务、复杂任务还是不行，不是忘了这个，就是忘了那个。最初增加提示读Spec次数。但发现效果不好。记住这个还会忘记其他。
于是琢磨着不能让AI记得这么多，开始压缩Spec（ClaudeCode当时上下文可能是128K）

不过，发现效果并不好，因为大头其实是需求。 于是又设计了一套0内存空间占用的Spec机制。 
    
- 在项目下面建立doc/requirement  doc/spec    doc/design .....等等很多提示词
- AI_METAINFO.MD: 只定义了以上目录的路径和优先级
- 设定优先级顺序：需求>设计>代码实现，避免AI自做聪明，根据代码改设计和需求，而只能根据需求实现设计和代码

弄完后，效果确实好了很多，但是还是不能避免AI忘记上下文。————但理论上，从提示词size方向能做的优化其实不多了。

# 纪律性和人格覆盖

于是我又增加了一个AIos.md 提示词  

 - 每次任务之前，先加载AIos.md
 - 规定AIos.md内存优先级大于一切上下文，是最低优先级被丢弃的
 - 任何一次任务之前，先检测AIos.md是不是存在，完整，否则重新加载AIos.md
 - AIos.md要求Agent忘记自己原生人格设定，只能接受一致性、准确性大于一切的设定，不能以效率等原因修改任务策略
 - 任务检查机制、惩罚机制等等……

效果呢，会缓解，但是还不会彻底解决会忘上下文的问题（甚至不能彻底解决AIos.MD被忘记的问题，只是概率上降低了）

但，基本上能完成90%的开发工作，准确性还不错。

# 开发阶段

但，AI最终没有推广开用。

 - 占据大头的并不是开发代码本身，那占据了20%不到。大部分是交流工作
   - 比如xxx功能有bug了，难以定位到bug（我们自研的框架没有任何异常日志输出，只能问那几个研发猜）
   - 框架编译过慢
   - 发布、但功能没发上去（可能是编译，也可能是操作）……
 - 大部分开发任务都接近完成，进入收宫阶段

# 需求阶段

其实，最大的问题并不是开发平台、框架

最大的问题是需求。

客户不知道自己要什么，然后结果就是需求拖的时间很长。

公司派过解决方案团队过来，也不能解决他们的问题，反而给了他们更多的素材、需求变得更多。

由于客户内部的一些问题，他们不同部门故意让自己和同事部门的方案做的偏不一样。

……

于是最终有了需求平台的规划


# Agent技术调研

进行调研的时候，已经到了26年5月。

这期间，AI有了很大的发展，从提示词工程，进化到上下文工程，然后又进化到Harness工程、产生了Skill、Agent、工作流等不同方法和流派。

我们调研了ClaudeCode，他核心架构其实很简单、但实际能力、效果和灵活性最强。他核心包含以下几个组件
1. 大模型：提供人工智能的大脑
2. MCP：私有域知识
3. Tools：AI的手脚
4. Skill：人的经验、方法、流程的沉淀
5. Agent：具备以上能力的特定任务的LLM的大模型的运行时
6. 工作流：多Agent协作完成大任务的协作方式
7. harness：提供Agent任务运行时基础设施、校验机制……目标是降低幻觉等、提供确定性任务结果。

这几种技术是逻辑上的，实际上某个实现覆盖范围经常重合。 

比如superpower既是skills，也是工作流。
即使同是skill，可能也完全可以南辕北辙。

      比如superpower基于脑爆和、TDD提供开发任务最佳实践。缺点是长会话机制、并发任务管理、
      trellis是适合并发任务管理，但仓库复杂度爆炸、spec复杂度爆炸（代码复杂度迁移到了文档复杂度） 
      而grillme是基于提问式提示词生成的最佳实践。

逻辑上，grillme是对的。——————提示词决定代码，那么只需要做好提示词文档就好了。

相比superpoer方案式的提示词生成方式。 ————前者是人诱导Agent产出方案，后者是Agent诱导人————它无疑是更全面、可靠、人机友好的。

并且它很好的对业务设计和技术设计进行了分离(/grill-me /grill-with-docs)
